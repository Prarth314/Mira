## Affected pages / surfaces
- App boot screen — first-launch wizard for permissions (Mic, Screen Recording)
- Main UI — transcript preview chip with cancel (700ms before action dispatch)
- Settings panel — provider switcher (Anthropic ↔ OpenAI), API key entry, "switching clears history" warning
- Sidebar — real telemetry from `systeminformation` (replaces `Math.random` placeholder)
- Error toast — single component, all `MiraError` kinds

## Key interactions to verify
- Press-and-hold Space → mic captures → release Space → transcript shows → action preview chip → action executes → spoken confirmation
- Esc during preview chip → action cancelled, no execution
- Settings → switch provider → toast confirms history cleared → next turn uses new provider
- "Open Calculator" spoken → Calculator.app launches on macOS
- "Describe what's on the screen" → screen capture → provider returns description → spoken aloud
- Provider 401 → toast → Settings opens with key field focused
- Provider 429 → spinner extends, no error if retry succeeds within 3 attempts
- First launch on clean machine → wizard prompts for Mic + Screen Recording permissions before voice loop is usable

## Edge cases
- Push-and-immediately-release Space (zero-duration buffer) → no provider call, no error toast
- Long press (30s+ utterance) → still transcribes, no buffer overflow
- LLM returns malformed action JSON → adapter rejects with `MiraError 'tool_parse'` → toast, no execution
- LLM emits unknown action.kind → rejected, toast
- LLM tries `open_url` with `javascript:` or `file:` → rejected at action validation
- LLM tries `launch_app` with shell metachars in name → rejected
- `set_volume` -1 or 101 → clamped to 0..100
- Provider switched mid-utterance → utterance discarded with toast
- App relaunched after permissions denied → wizard re-opens
- Whisper model partial download interrupted → resumed on next launch with checksum verification

## Critical paths
- End-to-end voice loop with Anthropic provider: press Space → say command → release → action runs → TTS confirms
- End-to-end voice loop with OpenAI provider: same flow, semantically equivalent action
- Settings flow: open settings → enter key → save → safeStorage encrypts → status shows green
- First-launch experience on a clean macOS user account: wizard, key entry, first successful command
- Vision flow: command requires screen context → describe_screen action fires → screenshot to provider → response synthesizes screen content + speaks

## Eval scope (LLM-judged)
- 20 spoken commands covering each action kind (`launch_app`, `open_url`, `set_volume`, `describe_screen`, `speak`)
- Run against both providers
- Judged by Claude on whether the right action.kind + args were emitted
- Tracks regressions when system prompt or tool definitions change
- Phase 3 dependency
